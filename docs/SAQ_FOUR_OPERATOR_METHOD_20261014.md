# 四算子版方法说明（开发候选）

这一版本用一个9×4的Q表选择Seeking候选的生成方式。每个动作持续100次真实函数评价，完整轮仍评价6个Tracing候选和4个Seeking候选。只有一套状态和调度器。

记候选父代的虚拟位置为x_i，真实位置为z_i，历史个人最优为p_i，全局最优档案为g，边界为l/u，预算进度为t。每个Seeking父代生成4个新候选；常规/同伴/反向动作修改随机20%坐标，至少1维。

| 动作 | 在选定坐标上的候选生成 | 作用假设 |
|---|---|---|
| 1 常规 | y = x_i + 0.25(p_elite-x_i) + 0.025(u-l)(1-t)·U(-1,1) | 沿原精英方向搜索 |
| 2 同伴 | y = x_i + 0.5(p_r-p_s) + 0.025(u-l)(1-t)·U(-1,1) | 使用群体差分方向，r/s/i互异 |
| 3 高斯 | y=g，随机1维d令y_d=g_d+(u_d-l_d)(1-0.9t)·N(0,1) | 在当前最好位置附近扫描一个坐标 |
| 4 反向 | y=z_i，选定坐标令y_d=l_d+u_d-z_i,d | 沿真实父代的对称位置尝试不同区域 |

替代动作的越界坐标反射到边界内。动作2与4是适合CSO Seeking结构的简化适配，并非老师原PSO更新式。所有候选共用原几何筛选与贪心接受；动作不会凭空获得适应度，也不会增加真实评价预算。

## 状态和反馈

状态 = 3种进度阶段 × 3种连续无有效改善状态。进度阶段以.3/.7为界；无改善计数为0、1–9、至少10个100FE窗口。窗口有效改善定义为全局最优降低量达到起始真实fitness IQR的1e-4，数值尺度使用初始IQR的1e-12作下限。

奖励：有效改善+10；否则窗口开始为严重停滞、且实际评价过高斯/反向候选时+.5；其余−1。+.5是搜索先验的奖励塑形，不能记作真实目标改善。同伴动作不会因名称包含“探索”就获得这项奖励。

Q更新使用alpha=.1、gamma=.9、100FE窗口的实际长度折扣；最后一个窗口bootstrap=0。epsilon按预算从.5降至.05。所有可行状态允许四动作学习，不将健康状态的Q表留空。零宽度搜索域只允许常规动作。

## 实验能回答什么

FO-Base验证原骨架；FO-Rule按健康常规、轻停滞同伴、严重停滞交替高斯/反向；FO-Random在相同四动作中均匀选；FO-Q在相同集合内学习。只有与规则及随机的结果比较，才能讨论学习调度提供的新增价值。
