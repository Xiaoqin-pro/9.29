# 三算法运行归档：29函数 × 10 seed

## 状态与适用范围

本批 870 条终点记录已生成。ASE-CSO/CLPSO 为仓库现有实现对照；标记为
`NRLPSO` 的第三组是**尚未通过来源一致性核验的 MATLAB 适配版**，不能作为
论文原版 NRLPSO 的正式复现结果。RLPSO/RLAM 未运行，等待冻结 actor 模型。

本次启动前只检查了一个函数的可执行性，没有完成承诺的来源一致性审计。
这是执行流程的失误。以下报告保留全部数据，并限制相应结论；没有修改原始
CSV，没有悄悄替换算法或重跑结果。

## 协议

- CEC2017：F1、F3–F30，D=30，边界 [-100,100]。
- Seed 101–110，每函数、每算法 10 次。
- 三组均使用 N=50 和同 seed 生成的相同初始种群。
- 每次上限 60,000 FE，包含初始化；MATLAB 4 个进程 worker。
- ASE-CSO 搜索参数保持冻结；NRLPSO 适配版使用 k=5。
- 三个方法在同一个函数/seed任务内依次执行，任务之间并行。
- 原始 CSV 在整批结束后一次写出，没有运行中断点 CSV。

## NRLPSO 来源一致性审计：未通过

来源：MetaBox commit `5565a281ce4e03efc1f6a41230507d5b66637ace`，
`src/environment/optimizer/nrlpso_optimizer.py` 和
`src/baseline/metabbo/nrlpso.py`。该来源本身是第三方实现，并非作者源码。
比对执行副本发现：

1. **邻域位置来源不同。** MetaBox 按距离得到索引后取当前 `population`
   的位置；MATLAB 版取 `pbest(ord,:)`。这直接改变速度参考与变异方向。
2. **Q 转移不同。** MetaBox 的 `update` 返回下一处理粒子的状态；适配版
   使用当前 action 作为更新目标状态。与论文按单粒子动作状态设计的关系
   需要另行核对，不能声称与 MetaBox 等价。
3. **学习率进程不同。** 适配版用逐粒子 update 次数除以
   `ceil((maxFEs-NP)/NP)`，从而很早降至0.1。论文公式(10)则按已用FE/总FE
   从1逐步减小到0.1。这是明确的移植问题。
4. **固定参数协议不同。** MetaBox 默认 NP=100、k=5；论文第4.2节推荐
   k=8。本批强制 N=50、k=5，与前述保留基线来源参数的计划不符。
5. **历史更新发生额外修改。** 适配版在普通改善时更新 `pbestCost`，
   MetaBox 的对应代码仅更新位置。这可能是修补源实现缺陷，但必须显式
   记录并依据论文判断，不能称为纯接口适配。
6. **追踪与可信状态未验收。** 适配版变异FE处未逐点评价轨迹填写，且
   Best.Cost与Best.Vector的更新顺序存在风险。本批只保存终点Cost，
   无法根据现有CSV确认每个返回位置都对应真实最优Fitness。

只完成6k smoke不等于通过移植回归。故本批不能支持“ASE-CSO优于原版
NRLPSO 18/29”的论文主张，也不应作为正式三算法总体排名证据。
