# 搜索难点隔离诊断（2026-10-04）

这不是新算法、不是正式性能排名，也没有改85c229e的算法、Fitness或冻结场景。项目根目录仍为八个MATLAB文件。所有诊断源码在本目录source，正式源码快照在production_source。

## 设置

- peaks地图；30粒子；每次3000次评价（含初始化）；每组5个seed。
- Full：调用原PSO/Fitness，N10/N15/N20 × wide45/tight12，共30次。
- RouteOnly：只搜索N个排序键。服务点间使用XYZ直线距离，等待/服务/客户及返仓时间窗仍保持；忽略地形、圆柱、角度及控制点，共30次。
- ControlOnly：N20、固定历史可行候选的订单顺序1..20。仅126个lambda/d/h均匀随机；没有用历史控制点。诊断副本将ready置0、客户/仓库due置1e9，以隔离几何，共5次。
- 诊断PSO从正式PSO逐段派生，保留pbest/gbest、.15速度上限、c1=c2=1.5、惯性调度和评价计数。Full模式逐项复现正式结果。没有重新发明一个只有gbest的算法。
- 相同场景wide/tight配对seed；不同维度隔离不是同一初始矩阵，不能作为公平算法排名或耗时性能比较。

ControlOnly几何可行为0/5。五次结果圆柱相交分别12、10、11、3、14次；地形违反均大于0，角度违反也均大于0。平均地形违反5.588、相交10次、角度违反41.222度。
RouteOnly没有评价几何，其GeometryFeasible/GeometryRate为1只是空约束成立，不表示能在真实地图飞行。Full N10-wide有一次几何安全，但时间仍不可行。
历史候选重新在冻结N20_tight完整模型下评价仍可行，只作为存在性检查，未注入种群。5次失败不能证明几何空间无解。

## 已定位的问题

1. 控制点独立搜索本身困难：即使去掉订单搜索和时间窗，也没找到安全几何。不能继续只归因于窗口或146维耦合。
2. 订单排序并非完全失效：简化N10/N15宽窗能够成功，N20宽窗部分成功；紧窗和规模仍使路由搜索困难。
3. 当前圆柱罚项有实测平台：同样10单位长的水平航段，穿透深度从2逐步减到0，碰撞count仍为1，成本保持110010；侧移到2.1完全离开才降到10。解析接触判为撞障正确，但只有计数未提供逐渐靠近边界的反馈。
4. 不同违规量使用不同单位和尺度，当前混合罚值不能直接说明哪个机制是根因；归一化/连续反馈值得下一步受控试验，不代表已证明改完就成功。
5. RouteOnly统计到每次更新约48%至72%的顺序实际改变，说明随机键平台存在，但不能说所有搜索都卡在完全不变的序列。

## 建议下一步（尚未实施）

只在ControlOnly诊断上，对照旧圆柱计数与连续安全距离/穿透缺口反馈。保留解析碰撞硬判据、全部地图/角度/高度限制、相同PSO/随机种群/评价预算。
先验证新反馈是否改善几何，再决定是否进入正式Fitness；不要同时改时间窗、罚函数归一化和路由算法。固定顺序始终只是诊断，不恢复引导初始化。
