# CEC2017 搜索内核开发实验

## 协议

- 函数：F1、F3、F6、F9、F10、F12、F15、F19、F22、F26。
- D=30，种群50，每次300000 FE（初始化50次计入），重复编号21–23，共90次运行。
- 同一函数/重复使用相同初始种群、InitSeed和SearchSeed；twister随机流。
- 固定Global-Cap2、Range Seeking、MR=0.4、SMP=5、CDC=0.2、SRD=0.05；关闭RL与Recovery。
- 每轮5 FE：Tracing 2、Seeking 3，每父代最多2次Seeking评价；4 workers。

## 三个版本的实际区别

| 版本 | 实现 |
|---|---|
| V0-GlobalCap2 | 原有Range候选；Tracing朝gbest移动并无条件接受 |
| V1-Elite | 个体已评价历史最优记忆；每猫从历史最优前20%中随机选精英；Seeking选中维度增加0.25倍精英方向；Tracing朝该精英移动，仅接受父代改善 |
| V2-EliteDiff | V1基础上，每个Seeking候选增加0.5倍两个历史个体的差分方向；Range步长尺度从1-progress改为max(0.2,1-progress) |

历史最优只从真实评价后的初始位置和候选更新，生成未评价候选时不更新适应度缓存。所有新候选先生成，再按本轮开始的gbest和中心筛选。

V1是精英记忆、双模式引导及Tracing保优接受的组合验证；V2是差分方向与步长下限的组合验证。它们不是单组件因果消融，不能把结果全部归因于某一个公式。

## 如何解释本轮

1. V1相对V0有较强开发信号。F1、F3、F9、F15、F19、F22均值改善明显，唯一均值退化的是F12（约50.6万升至107.9万）。F1配对只有2/3胜，且V0存在一次误差约509的好结果，均值改善不能解释为每次运行都更强。
2. V2在F6和F9表现很好，均值误差分别为0.719和19.03，但F1达到316万、F3约1658，显著差于V1。当前不宜把差分与非零步长组合设为默认搜索内核，也不能据此断言差分或步长下限各自无效。
3. 后期改善具有函数依赖性。按逐运行(60%误差-终点误差)/60%误差计算，V1在F1平均下降99.81%，F3平均下降99.53%；F6/F9分别约7.88%/20.75%。V2在F6/F9分别约56.73%/46.66%，体现出互补性，但尚不足以支持融合新版本。
4. V1平均时间50.55秒（V0约42.78秒），V2约119.05秒。V2时间开销与退化必须保留报告，当前没有证据宣称运行更快。
5. Seeking父代成功率由V0约26.57%降至V1约1.50%、V2约0.80%，这可能与候选生成及父代保优改变有关；总成功率不能单独代表最终搜索质量。当前CSV仅记录Seeking全局改善，后续如需解释Tracing收益应补相应诊断，不根据现有字段臆测原因。

## 研发边界与下一步

本轮仅有10个诊断函数、每函数3个开发seed，不能证明完整CEC2017上的优势。CLPSO没有用21–23这些seed配对重跑，上一批16–20的均值仅可作历史参照，不能作为本轮胜负统计。

保留V1作为搜索内核候选；下一步优先在其余19个函数上与V0和CLPSO使用新的统一seed比较，检查收益能否扩展。先不增加恢复或Q调度。若要归因V1收益，后续单独控制精英引导与Tracing接受规则，而非继续同时叠加模块。

旧入口默认searchCore=base，正式CEC与UAV入口未切换。本次没有动历史实验参数，也没有上传MAT历史。

## 文件

- raw_runs.csv、summary.csv：原始结果与均值/标准差/中位数/时间。
- comparison.csv：逐函数均值改变量和同seed配对胜负。
- ranking.csv、mean_error_by_function.csv：本轮排名和三版本均值。
- convergence.csv：90次运行每3000 FE的真实采样（共9000条），非逐FE完整历史。
- late_convergence.csv：逐运行60%与80%之后的改善比例。
- raw_runs_checkpoint.csv：完成时的checkpoint。
- main_cec_search_core_parallel.m：仓库根目录实验入口。
